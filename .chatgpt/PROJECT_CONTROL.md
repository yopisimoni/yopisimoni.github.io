## Operating rule
The bottleneck is distribution and conversion, not portfolio volume. Do not add new showcase projects unless outreach evidence shows a specific proof gap.

## Proof policy
- Label live, private, experimental and paused work accurately.
- Do not claim clean CI for repositories with failing checks.
- Prefer a working live demo over linking to a broken legacy source repository.
- Keep claims concrete and evidence-based; no invented client metrics or revenue.

## Revenue validation sequence
1. Keep the public portfolio credible and focused.
2. Align job/freelance profiles to the same positioning.
3. Send a small batch of highly targeted applications/proposals.
4. Track replies, calls, interviews and paid outcomes.
5. Improve proof only in response to actual objections or missing-evidence patterns.

## Definition of done
A portfolio change is done only when committed and the live GitHub Pages output is verified.
